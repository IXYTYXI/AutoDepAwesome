# Git HTTPS proxy implementation plan

User decision: source acquisition should use a proxy because direct GitHub connections repeatedly fail or exceed 120 seconds. The server already runs a localhost Mihomo endpoint; anonymous proxy tests read the requested branch three times in 1.1–1.4 seconds and shallow-fetch it in 1.6 seconds.

## Scope and design

Add the administrator-only optional `git_proxy_url` setting. The configured server value will be `http://127.0.0.1:7890`. Accept HTTP CONNECT, HTTPS CONNECT and SOCKS5H endpoints with explicit ports; reject userinfo, query/fragment, non-root paths, whitespace/control characters and malformed hosts. Proxy credentials are intentionally not supported by this setting. Default `None` preserves direct transport.

Pass this value to Git using a purpose-specific child environment variable and `--config-env=http.proxy=...`, not the parent shell environment or repository files. Apply it to HTTPS network acquisition commands only. Keep the repository address, allowlist, no-redirect rule, anonymous/private-repository credential separation and fixed-commit snapshots unchanged. Explicitly preserve origin and HTTPS-proxy certificate verification. Do not retry without the configured proxy. Do not add automatic retries or mutate user application source, images, manifests, SDKs, runtime network or AI calls.

## Execution

1. Add failing configuration and source tests for valid/invalid URLs, environment isolation, TLS settings, transport-only scope, unchanged default behavior, and proxy failures with no direct fallback. Verify failures before implementation.
2. Extend `Settings` / `load_settings` and `GitSource._git` minimally. Keep raw Git stderr private and retain accurate existing error categories rather than blaming the proxy for every failure.
3. Use a local CONNECT fixture returning an error to verify real Git attempts the configured proxy and fails without direct fallback. Run targeted tests, then the full Python suite and lint.
4. Document the administrator setting and bump the platform patch version to 0.5.1. Commit and push a reviewable branch; build and Linux-test an immutable release.
5. Pause platform API/worker while idle, back up configuration, set the localhost proxy, switch the version atomically, then restart only platform services. Verify installed Git source acquisition through the proxy and unchanged customer containers/routes/volumes/domain/port reservations. Do not restart Mihomo or Docker and do not submit the user's deployment.

## Acceptance

- Invalid configuration is rejected without disclosing its value.
- The proxy is absent from job snapshots, generated files and business container configuration.
- `main` is not silently substituted; the requested ref is always honored.
- The real public repository can be fetched as the awesome user through the configured proxy with its original commit intact.
- Existing business applications remain reachable during and after the platform update.
