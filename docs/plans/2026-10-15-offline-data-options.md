# 下线时选择保留或删除数据

用户确认的删除范围：该应用的业务数据，以及平台保存的密码、API Key 和密钥。默认保留。开发和验收不得删除现有业务应用的数据，不修改用户仓库的业务逻辑。

## 行为与边界

- 管理页下线弹窗使用两个选项卡片，默认“保留数据”。删除需要输入“删除 域名前缀”，弹窗有最大高度和内部滚动。
- API `dataPolicy` 为 `retain` 或 `delete`，省略时兼容旧调用。删除请求另带 `deleteConfirmation`。请求键绑定应用、上线版本及数据策略；结果未知时保持同一请求，不能默默切换策略。
- 入队时在数据库事务中冻结该应用所有未清除历史任务、配置空间及精确卷实例。若其他应用拥有相同配置空间，或相关任务仍在处理，则拒绝清理。
- worker 持独占锁，先记录秘密文件的元数据清单，再完成既有入口关闭、停止容器和运行资源清理。所有目标校验通过后，非强制删除无引用的原卷，并精确删除原秘密文件。已有清单不可替换；缺失项允许重试，新增或替换项会阻止继续。
- CLI 和页面秘密写入遵守同一 worker 锁及清理范围门禁。中断状态保留域名、端口和恢复门禁，不能把可能部分清空的旧应用自动上线。
- 确认全部清除后，原历史任务标记数据已清除，保留原快照和审计记录。旧补配表单失效。再次部署不继承旧卷身份；在新一代尚无数据时允许生成新的托管 MASTER_KEY。
- 两种下线方式完成后都释放域名、端口。清理不触及外部数据库、第三方凭据提供方、手工备份、源代码、部署记录或构建缓存。

## 实现与验收

分工覆盖 `storage.py`、`secrets_store.py`、`store.py`、`offline_data.py`、worker/runtime、API/CLI、管理页及对应测试。新增破坏性路径均先运行失败测试，再实现并运行相关回归。

验收覆盖保留默认值、精确确认、并发门禁、共享配置空间、停止容器引用、卷替换、秘密文件替换/链接/权限、元数据不含秘密值、删除中断、固定计划重试、旧表单失效、清空后重新部署、其它应用不变和缓存不变。

本机完整 Python/前端测试及静态检查通过后，用 Linux 安装包运行完整测试；真实 Docker 验收仅创建独立临时应用/卷/配置目录。平台升级时只切换平台代码并重启平台服务，对比现有应用、容器、卷、秘密元数据、域名路由、端口及配置，最后验证原公开 HTTPS 服务仍可访问。
