# 飞书登录与应用权限实施

范围：浏览器飞书 OAuth、平台独立会话、管理员引导、普通成员应用归属、成员权限、执行前撤权检查。用户明确选择同时开放普通成员。保留 Basic 兼容模式；Feishu 模式完全禁用 Basic 入口。不部署服务器、不启动 Docker Desktop。

1. 核对官方 OAuth v3、员工状态和应用可用范围；lark-cli 用独立 profile 做应用配置核验，不复用本机用户凭证。
2. 先写拒绝重放、跨租户、CSRF、会话过期、状态缺失和撤权测试，再实现身份与会话。
3. 在事务内固定应用归属、成员版本和任务身份；过滤所有读取入口；阻止凭证借用和幂等键跨用户混用。
4. 执行器在获取源代码、解密/冻结配置、停止旧版、启动、发布及提交成功前复核；系统恢复保持存储门禁。
5. 登录、退出、无权限、成员管理界面沿用现有绿色样式，检查键盘、长文本、移动尺寸、错误/加载状态。
6. 运行 Python 与 JavaScript 回归测试、静态检查及本地浏览器验证；人工审查，更新接入说明，合并到同一 main 并推送。真实飞书回调必须在管理员配置正式 app/callback 后验收。

本轮不把应用密钥加密、业务应用 SSO、审批流或 Skill 配对登录伪装为已实现。

## 验证结果

- Python 完整回归：1654 passed，1 skipped（本机文件系统不支持该 user xattr 用例）。
- Node UI 回归：97 passed；Ruff 与 git diff --check 通过。
- CUA/Chrome 使用真实静态页面和本地 fixture 验证桌面、375px、登录错误、会话过期、成员角色/转交/删除弹窗及管理员仓库授权。真实飞书 OAuth、目标 Linux/Docker 环境未在本轮验证。
- 独立审查发现的预存秘密空间认领、匿名失败日志无界增长已修复，并补有回归用例。
