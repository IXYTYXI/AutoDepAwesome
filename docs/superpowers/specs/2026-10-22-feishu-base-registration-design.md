# Awesome Deploy 飞书多维表格登记设计

日期：2026-10-22。用户确认：在指定飞书文件夹中新建专用 Base，包含「应用」与「部署记录」两张表；后台可靠同步，不上传密钥或原始日志。

## 边界

平台 SQLite 是应用、任务、权限和状态的唯一权威。Base 只是供人查阅的镜像，不接受反向编辑控制部署，也不保存密码、密钥、环境变量、原始命令或日志。写 Base 故障不得使部署失败。Base 默认保留在用户指定的文件夹，仅平台飞书应用获得编辑权。

## 数据

应用表每个稳定 app ID 一行：app ID、名称、仓库 HTTPS URL、当前或上次域名、负责人、当前部署 ID、状态、创建时间、更新时间。部署记录表每个任务 ID 一行：任务 ID、app ID、仓库 URL、ref、固定 commit（有则填写）、域名、状态、阶段、提交人、创建时间、更新时间。失败原因只留在平台页面，不复制到 Base。

初次启用时回填现有应用和任务。此后新应用创建、任务提交与状态更新、发布、失败、下线、负责人变更都能使对应镜像变脏。旧任务在迁移回填中按原状态登记，不重新执行。

## 同步

独立同步进程定期从平台 SQLite 读取安全投影，并把投影版本写入本地持久化同步账本，再调用飞书 Base OpenAPI。平台原有写入事务无需等待飞书。按 app ID / job ID 作为业务键查找、创建或更新远端行；本地保存 record ID。远端写入成功后才提交同步版本。失败时记录错误类别和下次重试时间，指数退避；进程重启继续。并发更新后旧响应不得清除新版本的待同步标记；下次扫描会重新比较源状态。同步进程独立于部署 worker，不持有部署锁，不阻塞部署请求。

## 配置与权限

平台配置显式提供 Base token 和两张表 ID；未配置时同步功能关闭。飞书服务应用使用现有保管的 App Secret 获取 tenant token，申请 Base 记录所需的最小读写权限，并仅作为该新建 Base 的编辑协作者。配置检查不输出令牌或密钥。只有飞书模式可启用。

## 验收

单元测试覆盖安全投影、初次回填、事务性标记、幂等查找和重试、并发版本、权限和错误路径；目标服务器以一条真实应用和任务执行同步并核对 Base 行，无需重新部署业务应用。测试创建的临时行应定向清理。线上页面或运维命令须能看见同步待办和失败状态。
