# 自动化部署 API 认证设计

用户方向：普通成员继续使用飞书网页登录；只有明确指定的人员或自动化来源才获得独立管理的 API 凭证。本阶段只解决认证，不改变任务队列与请求可靠性语义。

## 身份与权限

平台管理员在可信服务器终端为一个现有飞书用户签发具名凭证。来源类型为「指定人员」或「自动化来源」；自动化来源必须指定一位可追责的飞书用户。凭证只允许部署一个指定应用，或只允许创建新应用，不能同时拥有两种范围。有效期最多 90 天，管理员可列出和撤销。普通登录用户不会自动得到 API 凭证。

凭证仍受关联用户的启用、部署能力、租户、账号版本和应用成员权限约束。用户或应用权限撤销，以及凭证撤销或过期，都会使尚未执行的部署失效。已上线版本的系统恢复遵循现有规则。

## 调用与保存

专用 `/api/v1/automation/deployments` 路由只接受 `Authorization: Bearer`，不接受浏览器 Cookie 或 Basic 凭证；提交使用现有请求体和 `Idempotency-Key`，查询只允许访问该凭证提交的任务。浏览器现有 API 仍使用飞书会话、同源 Origin 与 CSRF。凭证是随机生成的高熵值，只在签发时输出一次；SQLite 中仅存 SHA-256 摘要、所有者、范围、过期和撤销时间，不保存明文。接受任务时记录凭证 ID，并用独立幂等命名空间，避免与网页登录请求混用。操作审计只保存凭证 ID，不保存原始值。

## 验收

测试覆盖有效凭证、缺失/错误/过期/撤销凭证、用户与应用撤权、范围隔离、跨凭证任务不可读、同凭证幂等重试、浏览器会话不能进入专用路由、凭证不能访问普通管理接口、数据库和安全响应不泄漏明文。目标服务器验收只创建和撤销临时凭证，不提交真实部署任务。
