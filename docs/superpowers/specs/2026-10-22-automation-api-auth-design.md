# 自动化部署 API 认证设计

用户方向：普通成员使用飞书网页登录后可自行获得个人 API 凭证；具名自动化来源由管理员单独管理。本阶段只解决认证，不改变任务队列与请求可靠性语义。

## 身份与权限

普通成员在飞书登录后的「API 凭证」页自行签发、列出、撤销本人个人凭证；创建与撤销需要最近 10 分钟的登录确认。管理员在可信服务器终端为一个现有飞书用户签发「指定人员」或「自动化来源」凭证；自动化来源必须指定一位可追责的飞书用户，由管理员单独列出和撤销。个人页面不显示也不能撤销来源凭证。范围可选单应用、仅创建新应用、创建并更新该成员有权部署的所有应用。旧凭证原有范围不因升级扩大。凭证有效期最多 90 天，不设有效凭证总数或来源提交任务数量的产品上限；具体任务仍经队列、应用权限和资源配额检查。

凭证仍受关联用户的启用、部署能力、租户、账号版本和应用成员权限约束。用户或应用权限撤销，以及凭证撤销或过期，都会使尚未执行的部署失效。已上线版本的系统恢复遵循现有规则。

## 调用与保存

专用 `/api/v1/automation/deployments` 路由只接受 `Authorization: Bearer`，不接受浏览器 Cookie 或 Basic 凭证；提交使用现有请求体和 `Idempotency-Key`，查询只允许访问该凭证提交的任务。浏览器现有 API 仍使用飞书会话、同源 Origin 与 CSRF。凭证是随机生成的高熵值，只在签发时输出一次；SQLite 中仅存 SHA-256 摘要、所有者、范围、过期和撤销时间，不保存明文。接受任务时记录凭证 ID，并用独立幂等命名空间，避免与网页登录请求混用。操作审计只保存凭证 ID，不保存原始值。

## 验收

测试覆盖有效凭证、缺失/错误/过期/撤销凭证、用户与应用撤权、范围隔离、跨凭证任务不可读、同凭证幂等重试、浏览器会话不能进入专用路由、凭证不能访问普通管理接口、个人自助与来源凭证隔离、连续创建及更新多个应用、数据库和安全响应不泄漏明文。目标服务器验收只创建和撤销临时凭证，不提交真实部署任务。
