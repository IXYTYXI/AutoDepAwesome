# 同组后端共享会话与可靠部署

用户已批准：A/B 初期同机，Redis 可独立部署；A 登录后共享会话，B 验证来源和申请人；A 数据库持久接收并重试；同步飞书同组接入文档。

A 是受信任的登录签发方，仅后端在完成 OAuth 后签发随机会话。Redis 使用来源隔离键、过期时间、签名 JSON；只存身份，不存密码或飞书 Token。A/B 必须使用同一个飞书应用身份命名空间，不能把不同 App 的 open_id 当成同一个人。远端 Redis 使用 TLS 和独立 ACL，URL 不内嵌密码。

B 新增显式委托来源凭证和 integrations API。普通凭证不能代理用户。B 绑定来源和实际申请人，以申请人的本地权限执行；不信任 A 传入的角色。B 按同应用、同企业 open_id 创建普通用户或匹配现有用户，不恢复已禁用账号。

A 受理时校验 Redis 并将请求与签名受理凭据事务保存到 SQLite。凭据绑定来源、用户、请求 ID、完整请求内容和受理时间。首次在线直调 B 校验 Redis；持久投递提交签名凭据，不受后续退出登录影响，但仍受本地停用、来源撤销及部署权限限制。凭据不含 Cookie、密码、飞书 Token，不能改请求后复用。服务凭证轮换不得改变来源级幂等键。

Redis 负责会话；数据库保存请求底账。提交、状态查询、超时重试、明确拒绝和等待运维处理分开；不使用 Redis Pub/Sub 作为唯一可靠队列。A、B、Redis 同机不能抵抗整机故障。现有部署 worker 仍串行，不声称并发执行已扩容。飞书应用/部署表继续异步记录，A 端数据库为待投递请求权威记录。

A 仓库、Redis 端点尚待用户提供；在缺失时完成 B、可复用 A SDK、测试与接入文档，不声称外部 A 已接通。
