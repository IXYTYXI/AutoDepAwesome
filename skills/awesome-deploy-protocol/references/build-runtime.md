# 构建与运行契约

这些约束影响架构与依赖选型，应在写业务代码前确认。开发者不需要部署平台、Redis 或平台管理登录才能按本页开发。

## 构建交付

使用源码构建时，仓库必须包含 Dockerfile、所有 COPY 输入，以及构建需要的离线依赖/产物。Dockerfile 中 EXPOSE 不会启动程序，也不能替代实际监听。

构建 RUN 默认无网络；不能把 RUN npm ci、pip install 或 apt update 的在线成功当作部署前提。可用的方案有：准备与目标 Linux 架构匹配的离线依赖；在合适基础镜像中预置依赖；或构建好业务镜像并在清单中用 image 引用。镜像必须可由服务器实际拉取，不能仅存在开发者本机。

没有第三方依赖的项目无需为了形式新增锁文件。依赖存在时保留锁定版本和构建来源，不把 macOS 的 node_modules、虚拟环境或本机二进制当作 Linux 交付物。多阶段构建也不自动获得网络权限。

平台拉取基础镜像并固定摘要，保持正常缓存。Dockerfile 可以先写字面标签；不能仅因开发者没手写 digest 就判定不合格。执行器处理镜像引用不授权修改用户业务源码。

镜像自身预声明的 VOLUME 或 ONBUILD 也会被执行器拒绝，不能只检查当前 Dockerfile 有没有这些指令。镜像与离线依赖必须匹配目标 Linux CPU 架构；本协议不假定所有目标服务器都是同一种架构。

## Dockerfile 语法边界

允许 FROM、RUN、COPY、ENV、WORKDIR、USER、EXPOSE、LABEL、CMD、ENTRYPOINT、ARG、STOPSIGNAL。每条指令单行书写。

当前不支持：反斜杠续行、heredoc、自定义 # syntax/# escape/# check、动态 FROM、FROM flags、FROM 前的 ARG、RUN flags/mount/network 覆盖、ADD、VOLUME、ONBUILD、HEALTHCHECK。

命名多阶段构建可用。COPY flags 只允许 --from=前序已命名阶段，不能用数字阶段、外部镜像来源、--chown 或 --chmod。COPY 的真实输入必须存在于仓库上下文，不能通过符号链接取宿主机文件。

包内单服务与双服务示例各有完整 Dockerfile 和标准库示例程序，它们演示无联网安装的最小构建。示例页面属于示例自身；检查已有业务时不得用它替换原页面、API 或数据实现。

## 受限运行环境

| 项目 | 应用必须满足的条件 |
| --- | --- |
| 身份 | 非 root 数字 UID/GID；参考 65532:65532。运行身份由平台设置，不能依赖用户名、root 或自行提权。 |
| 文件系统 | 根文件系统只读；不能在 /app、/root、/var/cache 等任意目录写运行数据。 |
| 临时目录 | /tmp 为最多 64 MiB 的 tmpfs，noexec/nosuid/nodev，不持久；不能依赖在这里执行下载或编译出来的程序。 |
| 持久目录 | 只有显式声明的 /data 卷可持久保存业务文件；需有相应权限和配额。 |
| 网络监听 | HTTP 服务绑定 0.0.0.0，端口与清单一致。PORT 只是普通变量，只有应用实际读取才生效。 |
| 权限与进程 | 不依赖特权、宿主机挂载、Docker socket、附加 capability；参考进程上限 128、文件描述符上限 1024。 |
| 日志 | 输出到 stdout/stderr；避免将秘密或完整认证头写入日志，也不要依赖不断增长的磁盘日志。 |

Python 可使用 -B 或 PYTHONDONTWRITEBYTECODE=1 避免写字节码；前端构建在交付阶段完成，不在只读容器启动时临时下载和编译。SSR 框架或 Nginx 等程序的缓存、pid、临时目录必须与受限环境兼容；不能只换 USER 就声称可运行。

不要以关闭鉴权、删除数据库调用、替换模型请求、返回假数据或只测演示页来绕过运行问题。新项目按需求实现真正业务；已有项目若必须变更业务才能适配，说明具体原因并由用户决定。

## 网络与外部服务

构建网络与运行网络是两项独立设置。运行时可能是 internal，也可能启用受限公网 HTTPS；必须以目标平台实际能力为准，不能声称所有容器必然能访问外部模型。

受限公网 HTTPS 模式允许受策略控制的公网 IPv4 TCP 443，不代表任意端口、私网地址或本机服务可访问。使用外部模型/对象存储时，确认域名解析、端口、TLS、请求超时、流式响应和错误处理，并将必要能力列入交付说明。平台模式不满足业务时报告阻塞，不擅自换接口、协议或关闭 TLS 校验。

当前新生成的业务代理配置使用 proxy_connect_timeout 5s、proxy_read_timeout 300s、proxy_buffering off；历史路由或目标环境可能不同，须以有效配置为准。这些设置不代表整个模型调用有无限等待保障，也不自动处理应用和客户端的超时、断连或重试。

应用网关模板没有单独指定 client_max_body_size，上传请求大小受目标 Nginx 的继承配置及应用自身限制影响。50 MiB 持久额度不代表允许单次上传 50 MiB。开发上传功能时将所需请求体上限交给运维确认，并测试超限响应；不能仅靠提高业务代码中的上传上限声称可用。

容器中的 127.0.0.1 是该容器自身，不能直接用于访问另一台服务器或宿主机服务。内部 Web 服务之间按 dependsOn 和实际服务名/端口设计通信。独立 PostgreSQL、Redis、消息队列、后台 worker 或迁移钩子目前不由清单托管；外部服务只有在平台策略和业务授权允许时才能使用，不能强制改成 SQLite 或删除任务功能。

## 存量项目与更新

保留启动方式、业务路由、鉴权和数据语义。选择合适的构建/配置映射可以适配部署，但“部署成功”不是改变业务行为的授权。

有持久数据的更新可能短暂停机，候选版本对数据的写入不会因回退镜像自动撤销。按业务需要设计数据兼容性、初始化、升级和恢复方案；平台不提供迁移钩子，也不自动改写数据库结构。
