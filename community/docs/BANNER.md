# 首页 Banner

前端只请求本站 `GET /api/v1/banner`，返回统一 Envelope，`data` 包含 `item`、`updated_at`、`stale`。`item` 是指定视图内按记录创建时间倒序排列的第一条；表中没有记录时为 `null`。分页读取完整结果后按飞书系统 `created_time` 比较，修改旧记录不会改变顺序；创建时间相同则保持视图原顺序。

## 飞书字段

| 字段 | 类型 | 展示规则 |
| --- | --- | --- |
| 标题 | 文本 | 可空；去除首尾空白后为空时隐藏标题 |
| 描述 | 文本 | 可空；为空时不渲染描述段落 |
| 封面 | 附件 | 取第一个附件；为空或图片加载失败时使用现有蓝色品牌矢量封面 |
| 链接 | 超链接 | 可空；仅接受 HTTP/HTTPS 链接，无有效链接时不显示按钮 |

最新记录即使标题或全部展示字段为空，也不会跳过它选择旧记录。表中没有记录时，首页使用 OWS Community 默认品牌 Banner，不显示按钮。浏览器旧版本保存的 Banner 不再读取；首页编辑、页脚管理和编辑表单均已移除。原活动详情地址仍可读取当前 Banner，首页按钮直接打开表里的链接。

上传封面展位固定为 16:9，随屏幕宽度响应式缩放；图片居中等比完整显示，不裁切、不拉伸。方图、竖图或超宽图的空余区域使用蓝灰色底色，图片自身比例不再改变展位高度。推荐封面分辨率 1920×1080，小图放大可能模糊。有封面时隐藏品牌装饰，标题、描述及链接按钮（若有）放在图片下方。

## 缓存与图片

- 共享来源 key：`<prefix>:banner:v2:<sha256(app_id|base|table|view)前24位>`，不按用户复制。
- `:fresh` 有效期为 **86400 秒（24 小时）**，命中不会续期；过期后的请求先争抢 60 秒刷新锁，成功者查询飞书，原子写入新快照和图片索引后返回前端。
- `:snapshot` 和 `:media:<hash>` 从最后成功刷新起保留 7 天。刷新失败返回旧快照并标记 `stale=true`，15 秒内暂停重试；首次读取失败且没有旧快照时返回统一错误。
- 空表也是有效结果，缓存 24 小时；表里填入或修改内容后，最迟在新鲜期到期后的首次请求生效。这是按需刷新，不是定时任务。
- Redis 故障返回统一错误，不绕过缓存查询飞书。
- 图片通过鉴权接口 `GET /api/v1/banner/media/{hash}` 获取，首次由后端下载、去除元数据并生成最大 2400×1600 的 WebP，后续读本地磁盘。Redis 只存索引，不存图片二进制，也不向前端返回附件 token 或临时下载地址。
- 更换附件产生新图片 URL；删除附件后在下次快照刷新时恢复默认封面。旧文件不再被新 Banner 引用，当前不会主动清理磁盘文件。

## 配置与部署

```dotenv
OWS_COMMUNITY_BANNER_TABLE_ID=tblcdBjCswJfsUgr
OWS_COMMUNITY_BANNER_VIEW_ID=vewx9vQ6cz
OWS_COMMUNITY_BANNER_CACHE_SECONDS=86400
OWS_COMMUNITY_BANNER_STALE_SECONDS=604800
OWS_COMMUNITY_BANNER_SOURCE_TENANT=<与其他内部数据源相同的租户>
```

复用现有飞书应用、Base token、Redis 配置及 `MEDIA_ROOT`。所有 Banner 和封面请求都验证本站身份，并检查配置的来源租户。本机图片保存到 `var/media/banner/`；服务器设置独立持久化 `MEDIA_ROOT`，升级时保留 Redis 数据卷和图片目录。多台服务器必须共用图片存储。浏览器使用相对 API 路径，无需写死本机地址。

应用必须具有该表及四个字段的读取权限。当前模块没有网页编辑接口，内容统一在飞书维护。

运营修改后需要立即生效，可在本机或服务器项目目录执行 `uv run python -m scripts.refresh_banner`，然后刷新网页。命令只让 Banner 新鲜标记失效，并经过正常刷新锁读取飞书；保留旧快照，不清理登录、案例或人员缓存。
