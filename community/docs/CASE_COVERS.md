## 数据和图片流向

前端 → 本站后端（身份、租户校验）→ Redis；快照过期后由单个刷新者读取飞书，再原子写入快照与附件索引。

- 共享键：`cases:v3:<应用+Base+表+视图摘要>`，不是每用户复制。
- `:fresh` 默认 1800 秒；`:snapshot`、`:media:<摘要>` 默认 604800 秒。读取不续期。
- 数据刷新失败保留旧快照并标记 stale；15 秒失败冷却。缓存与备份都不存在时返回统一错误，不伪装成空列表。
- 图片 URL：`/api/v1/cases/media/<64位摘要>`，摘要包含来源缓存键与飞书 file_token。前端不会拿到 file_token、附件临时下载地址或应用密钥。
- 首次请求：后端校验该图片仍属于当前展示的案例，查询 Redis 附件索引，再读取磁盘缓存；磁盘缺失才调用飞书下载。原文件有大小限制，解码检查格式/像素，去除元数据，最长边 1600px 等比缩小为 WEBP，原子写盘。
- 图片下载使用 Redis 锁合并同图并发，速率槽控制上游访问，失败冷却 30 秒。
- 缓存目录：`OWS_COMMUNITY_MEDIA_ROOT/cases/<摘要>.webp`。Redis 存结构化快照和索引，不存图片二进制。
- 更换附件会换 file_token，因此 URL 自动变化；清空封面后使用默认插图。成功刷新快照后，旧图片和已隐藏案例的图片端点返回 404，即使文件仍在磁盘也不会直接返回。
- Redis 丢失时重新读表恢复索引，仍存在的磁盘图片可继续复用；单独的附件索引被淘汰时也会经共享刷新锁重建。
- 飞书故障时可使用 7 天内旧快照。隐藏/撤回以成功同步后的快照为准，不承诺在飞书不可达时立即感知撤回。

## 开发与服务器

开发默认使用项目的 `var/media/cases`。服务器配置绝对路径，例如 `OWS_COMMUNITY_MEDIA_ROOT=/srv/ows-community/media`，确保应用用户有读写权限，并挂载到持久磁盘/容器 volume；部署代码时保留此目录。Redis 使用已有独立 OWS Redis。

多 worker 共享同一磁盘目录；多服务器若要复用文件，应挂载共享存储，否则每台服务器各自生成一份缓存。单文件 Redis 下载锁会短暂协调这些机器，未能等到其他机器的本地文件会返回暂时不可用，前端回退插图，下一次请求可自行填充本机缓存。

Nginx `/api/` 转发给后端。**不要把 media_root 配成公开静态目录，不要给这些带身份的 API 做公共 proxy_cache**；图片响应由统一中间件设置 `Cache-Control: no-store`，每次使用都经过身份及当前案例可见性校验。

磁盘缓存不使用 Redis TTL 自动删除；替换后的旧版本不可再经端点访问，但文件仍占空间。可在维护窗口按当前快照引用及保留期清理，不能清理 Redis 后直接把所有磁盘文件当作公开资源。

## 前端

首页档案卡片、案例库和详情页统一使用 `CaseCover.vue`。远程案例仅接受本站的 cases/media URL；使用懒加载（详情图立即加载）、异步解码、失败回退，图片更换后重置错误状态。

固定画框、`object-fit: contain` 完整等比展示；图片的原始横竖尺寸不影响卡片区高度。保留已有档案 UI 与响应式断点。
