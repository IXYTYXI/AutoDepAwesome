同组网页项目接入 Awesome Deploy API｜后端实施手册

适用版本 0.11.8，更新于 2026-10-26。本文面向同组项目开发者和 AI：A/B 先同机部署，Redis 可迁移。A 业务项目尚未创建，本次交付可接入组件、项目搜索和进度查询能力，不代表 A 已完成真实登录联调。

浏览器只访问 A；内部接入凭证、平台来源凭证、签名受理凭据均不得下发到前端。A 返回 202 表示申请已保存，B 返回 202 表示部署已入队，都不代表上线成功。

1. 服务与身份

A 是同组项目的后端，B 是 Awesome Deploy。A 可以使用自己已验证的登录态，也可以继承可信上游服务验证过的实际用户身份：后者必须通过可信的服务端登录校验取得身份和剩余有效期，再用受保护的内部凭证签发共享会话，不能接收浏览器自报的 openId、角色或负责人。会话存 Redis，默认 8 小时绝对过期，可配置更短时间，无滑动续期。B 验证来源凭证及共享身份，按实际用户在 B 中的本地权限搜索和部署。只接受与 B 相同飞书 App ID、tenant_key 的 open_id；不同 App 的 open_id 不能直接互换，也不按姓名匹配。

现行本机地址：Redis 127.0.0.1:6391；A 端适配服务 127.0.0.1:8099；B 127.0.0.1:8088，内部 HTTP 设置 Host 为 awesome.guanghexinzhi.cn。浏览器只访问 A，不能访问 8099 或持有内部凭证。容器中的 127.0.0.1 是容器自己；若 A 以后部署在容器，必须先配置受控的宿主机连接，不要直接开放公网端口或使用 host 网络来绕过平台策略。

继承登录态指复用可信后端已经验证的实际用户身份，不复制 A 或上游服务的 Cookie、密码、飞书 access_token 或 refresh_token 给 B。Redis 只保存签名身份和有效期。若 B 将来需要以用户身份读取或创建飞书文件，那是另一项 OAuth 资源授权；当前部署链路不需要。部署结果登记使用平台已有的飞书应用身份。

1.1 三类身份与项目权限

指定后端的专用凭证证明“哪个服务在调用”，共享 sessionId 证明“实际是哪位登录用户”。两项同时校验。普通用户可以经 A 后端的专用委托凭证加本人 sessionId 搜索获授权项目；个人 personal Bearer 不能直接调用该接口，不等于普通用户禁止搜索。服务不会因为与 B 位于同一台服务器，或来源凭证绑定了管理员，就自动获得全项目访问权限。

专用来源凭证不替代用户授权，不继承凭证持有人的管理员权限；部署仍按实际申请人校验。

例如 Alice 拥有项目甲，Bob 拥有项目乙且没有甲的授权：Alice 搜索只返回甲，Bob 搜索只返回乙。若 Alice 将甲的 maintainer 权限授予 Bob，Bob 才能搜到并更新甲；更新后甲的负责人仍是 Alice，本次任务提交人是 Bob。有效且 can_deploy=true 的管理员可以搜索甲和乙。指定后端使用 Alice 的 sessionId 时仍只有 Alice 的范围，不能借用服务凭证扩大范围。

2. A 后端接入顺序（任何语言均可）

以下接口都由 A 后端调用，携带 Authorization: Bearer <内部接入凭证>。配套 Skill 的客户端默认连接 http://127.0.0.1:8099，自动读取 /etc/awesome-team/intake-token；也支持 AWESOME_INTAKE_TOKEN 或 AWESOME_INTAKE_TOKEN_FILE，一次配置后无需反复填写。由其他系统账号运行时，由管理员给该服务提供可读的凭证配置。

实际可用 Key、配置方法与客户端用法见 同机服务 Key 与快速接入。可分发 Skill 位于仓库 skills/awesome-deploy-integration。内部 Key 由业务后端使用，不放入浏览器脚本。

  1. A 自己完成 OAuth 校验，或通过可信后端确认上游服务的实际登录身份与剩余有效期后，调用 POST http://127.0.0.1:8099/sessions。把返回 sessionId 关联到 A 的服务端登录上下文，不交给用户填写。
  2. 用户提交部署时，A 检查自己的申请权限，从服务端登录态取 sessionId；给此次业务申请生成并保存固定请求 ID，调用 POST /requests。
  3. 返回 202 表示请求已事务落入 A 适配服务数据库。前端显示“已受理”，后台通过 GET /requests/{requestId} 查询。GET 不创建任务。
  4. 用户退出 A 时，调用 POST /sessions/revoke。已持久受理的任务继续处理；后续新申请不能使用旧会话。
  5. A 向前端提供请求查询时，必须再次校验 requestId 属于当前用户，或具有该项目的部署详情读取权限（admin、owner、maintainer；仅 viewer 不足）。内部查询按整个来源服务授权，不能据此向用户暴露其他人的请求。

会话签发请求（identity 必须取自 A 已验证的 OAuth 结果，或可信上游后端验证后的同命名空间身份）：

{"identity":{"appId":"cli_aa04dd8797f8dbd1","tenantKey":"平台约定的企业标识","openId":"ou_实际登录用户","name":"实际显示名"},"ttl":28800}

返回 {"sessionId":"随机不透明标识","expiresIn":28800}。若 A 现有登录剩余有效时间不足 8 小时，ttl 取剩余秒数。退出请求：{"sessionId":"原会话标识"}。A 重新登录时先撤销旧共享会话，再签发新会话。会话签发、退出不能用前端未经核实的用户信息调用。

提交部署请求：

POST /requests HTTP/1.1
Host: 127.0.0.1:8099
Authorization: Bearer <内部接入凭证>
Content-Type: application/json
Idempotency-Key: project-a-request-001

{"deployment":{"repository":"https://github.com/your-org/your-repo.git","ref":"main","subdomain":"demo"},"sessionId":"服务端保存的共享会话标识"}
{"requestId":"project-a-request-001","status":"pending","jobId":null,"appId":null,"error":null,"deployment":null}

B 接收后 jobId、appId 非空，A 外层状态 submitted。部署排队、执行阶段和结果看 deployment；同组调用方可按第 2.2 节返回的 pollAfterSeconds 查询进度。202、pending、submitted 都不表示已上线。

更新已有应用：仍提交 POST /requests，在 deployment 中加入 appId，仓库与当前绑定域名须匹配，申请人必须有该应用的部署权限。deployment.ref 可省略，默认 main；显式传入其他分支、标签或完整 commit 时按指定版本部署。页面“项目名称”对应 deployment.subdomain：1–7 位小写字母、数字或中划线，首尾为字母或数字，不含中文、空格或大写字母，并与 awesome.yaml 的 app.subdomain 一致。每次新部署新请求 ID；同次超时重试始终保留 ID 和请求内容。请求 ID 为 1–128 位 [A-Za-z0-9._:-]。一次来源凭证可持续创建和更新多个获授权应用，没有累计申请数量上限；现有 worker 仍串行执行，受资源硬配额限制。

2.1 搜索项目并更新部署

2.1.1 按负责人查找项目

普通用户只能查询本人拥有或明确授予 maintainer 权限的项目及其相关负责人；管理员可查询全部项目及其相关负责人。该接口不提供全员通讯录，没有项目或没有可见项目的人员不会出现。姓名可能重复，必须按 ownerId 区分并由操作者确认目标，不能自动选第一项。

sessionId 表示当前操作者，ownerId 表示要筛选的当前项目负责人。ownerId 是平台用户 ID，不是飞书 open_id，也不是来源凭证持有人 ID。查询负责人不会切换登录身份、授予权限或改变项目归属。

A 使用内部接入 Bearer 调用 POST http://127.0.0.1:8099/owners/search。B 对应接口是 POST /api/v1/integrations/owners/search，使用专用来源 Bearer。两层 JSON 相同。

{
  "sessionId": "REPLACE_WITH_SHARED_SESSION_ID",
  "query": "示例用户",
  "limit": 20,
  "offset": 0
}
{
  "items": [
    {
      "ownerId": "33333333333333333333333333333333",
      "displayName": "示例用户"
    }
  ],
  "total": 1,
  "limit": 20,
  "offset": 0,
  "nextOffset": null
}

确认负责人后，使用当前操作者的同一 sessionId 调用 POST /apps/search：

{
  "sessionId": "REPLACE_WITH_SHARED_SESSION_ID",
  "ownerId": "33333333333333333333333333333333",
  "query": "",
  "limit": 20,
  "offset": 0
}

ownerId 可选，省略或 null 保持原搜索范围；传入时为 1–128 字符非空、非纯空白平台用户 ID。query 在负责人搜索中匹配姓名或 ID，在项目搜索中匹配项目名称、仓库或 appId。两者均最多 200 字符；limit 默认 20、范围 1–20；offset 默认 0、范围 0–1000000。先按权限过滤，再筛选和分页；未知或不可见负责人返回空结果。

未分配负责人的历史项目仅管理员可见，应用结果的 ownerId/ownerName 为 null，负责人候选列表不会伪造一个用户。负责人账号停用不删除其项目或历史归属；操作权限取决于当前操作者。查找和筛选不会创建任务，不要求 Idempotency-Key。

2.1.2 搜索项目与更新部署

A 后端调用 POST http://127.0.0.1:8099/apps/search，携带内部接入 Bearer；适配服务使用平台专用委托来源凭证调用 B 的 POST /api/v1/integrations/apps/search。两层请求体相同，sessionId 必填，只能取自已验证的服务端登录上下文，放入 JSON，不放在 URL。查询时实时读取 Redis 检查会话，不接受 receipt 代替，也不能省略会话改用无用户服务身份。所有这些接口仅供后端，内部接入凭证与来源凭证不能发送到浏览器。

POST /apps/search HTTP/1.1
Host: 127.0.0.1:8099
Authorization: Bearer <内部接入凭证>
Content-Type: application/json

{"sessionId":"服务端保存的共享会话标识","query":"demo","limit":20,"offset":0}

query 默认为空字符串，最多 200 个字符；不区分大小写，按项目当前/历史名称（subdomain）、仓库地址或 appId 包含匹配。limit 为 1–20 的整数，默认 20；offset 为 0–1000000 的整数，默认 0。空 query 列出当前用户有权部署的项目：普通用户仅限自己或已获 owner/maintainer 授权的项目；有效且 can_deploy=true 的管理员可列出全部项目。没有匹配时 items=[]、total=0。

{
  "items": [
    {
      "appId": "已有应用编号",
      "projectName": "demo",
      "repository": "https://github.com/your-org/your-repo.git",
      "subdomain": "demo",
      "lastSubdomain": "demo",
      "domainBound": true,
      "ownerId": "33333333333333333333333333333333",
      "ownerName": "示例用户"
    }
  ],
  "total": 1,
  "limit": 20,
  "offset": 0,
  "nextOffset": null
}

先按实际用户的部署权限过滤，再按 ownerId、query 筛选并计算 total 和分页，因此不能通过总数推断其他人的项目。nextOffset 为下一页偏移；null 表示没有下一页。下一页保持 ownerId、query、limit 和会话不变，offset 使用 nextOffset。来源凭证即使绑定管理员，也不会扩大实际用户的搜索范围；能搜索到不保证提交时权限或域名未发生变化，部署接口仍重新校验。账号失效或 can_deploy=false 时拒绝访问，不以空列表掩盖权限问题。

domainBound=true 时，更新保留返回的 repository、subdomain，并携带 appId。domainBound=false 时 subdomain=null，lastSubdomain 只是曾用名称，不代表现在仍可用；先选择空闲且符合 awesome.yaml 的项目名称，不能直接把 null 或历史名称当作已保留域名提交。搜索结果只供选择，出现多个匹配时必须由用户明确选择 appId。

搜索不创建部署请求，不使用 Idempotency-Key，也不会进入部署队列。会话失效返回 401，来源凭证过期/撤销也可能返回 401；先核对用户会话，来源凭证由运维轮换。权限拒绝为 403，参数错误为 422，Redis 或 B 暂不可用为 503。不可用时应显示查询失败，不把错误当成空列表；无须申请额外飞书通讯录权限。

以下连贯示例演示“搜索 → 选定 appId → 更新 → 查询进度”。authenticated_user 与 deployment_request 是 A 自己的已验证登录对象及持久业务记录，需要接入实际代码；这是后端集成示例，不是可直接粘到浏览器执行的脚本。HTTP 错误应交给 A 处理并向用户展示：搜索失败不提交，POST 响应不明时保留相同业务 ID 与请求内容重试，GET 失败时稍后恢复查询。

# Python 3；仅在 A 后端执行。Token 由运行环境注入，session_id 来自服务端登录态。
import json, os, time
from urllib.request import Request, urlopen

base = "http://127.0.0.1:8099"
token = os.environ["AWESOME_INTAKE_TOKEN"]
session_id = authenticated_user.shared_session_id  # 接入 A 自己的登录对象
request_id = deployment_request.id  # A 已持久保存的本次业务申请 ID；重试不换 ID

def call(path, body=None, key=None):
    headers = {"Authorization": "Bearer " + token}
    data = None if body is None else json.dumps(body).encode()
    if body is not None:
        headers["Content-Type"] = "application/json"
    if key is not None:
        headers["Idempotency-Key"] = key
    with urlopen(Request(base + path, data=data, headers=headers), timeout=15) as response:
        return json.load(response)

page = call("/apps/search", {"sessionId": session_id, "query": "demo", "limit": 20, "offset": 0})
# 实际页面可展示 page.items，让用户选择；示例仅接受唯一匹配。
if page["total"] != 1:
    raise ValueError("请明确选择项目，不能自动部署第一个搜索结果")
app = page["items"][0]
if not app["domainBound"]:
    raise ValueError("请先选择空闲且与清单一致的项目名称")
body = {"sessionId": session_id, "deployment": {
    "appId": app["appId"], "repository": app["repository"], "subdomain": app["subdomain"]
}}  # ref 省略，默认 main
result = call("/requests", body, request_id)
deadline = time.monotonic() + 900
while result["pollAfterSeconds"] > 0 and time.monotonic() < deadline:
    time.sleep(result["pollAfterSeconds"])
    result = call("/requests/" + request_id)
    job = result.get("deployment")
    if job:
        print(job["statusLabel"], job["phaseLabel"])
# A 外层 pending/submitted 不能当作上线成功。
# 若仍未结束，保留 requestId，之后继续 GET；不要生成新的部署请求。
job = result.get("deployment")
if job and job["terminal"]:
    print(job["status"], job["error"], job["url"])
elif result["status"] == "rejected":
    print(result["error"])

2.2 查询投递与部署进度

A 后端使用内部接入 Bearer 调用 GET http://127.0.0.1:8099/requests/{requestId}。内部查询按来源授权，能读取本来源记录。A 向前端返回进度前必须再次校验该 requestId 属于当前用户，或具有该项目的部署详情读取权限（admin、owner、maintainer；仅 viewer 不足）；仅知道 requestId 不构成授权。查询不要求把 sessionId 放 URL，也不要求再次提交部署。

字段

含义

requestId / jobId / appId

A 业务请求 ID / B 部署任务 ID / 应用 ID；B 未受理时后两项可能为 null。

status

A 外层 pending=已落库待投递；submitted=B 已受理，仍可能排队/执行；rejected=平台明确拒绝。取得 B 终态后为 succeeded、failed、recovery_required 或 cancelled。

createdAt / updatedAt

A 请求的创建/最后处理时间；Unix 秒数。

pollAfterSeconds

外层进行中建议 5 秒查询一次；外层终态（含 rejected）为 0。

error

A 投递错误摘要；真正的部署失败还需查看 deployment.error。

deployment

最近一次从 B 查询的任务快照；还未取得时为 null。显示部署进度用其中 status、phase 和对应中文标签。

B 任务快照包含以下字段。A 外层 submitted 只表示投递已成功，不表示部署完成；没有百分比字段。A 在任务结束后不持续刷新在线状态，因此最终缓存里的 active/url 是最后同步时的状态。若要确认今天是否仍在线，A 后端用来源凭证直接 GET B 的任务接口，不能仅据 A 的历史快照判断。

字段

含义

id / appId

本次任务 ID / 应用 ID；不要混用。

status / statusLabel

机器状态码 / 中文说明；queued、running 表示未结束；succeeded、failed、recovery_required、cancelled 是终态。

phase / phaseLabel

当前阶段码 / 中文说明，如 build / 构建镜像、health / 健康检查。阶段耗时不固定，不返回虚构百分比。

terminal

布尔值；true 时停止常规进度轮询，不代表部署成功。

createdAt / updatedAt

Unix 时间戳，单位秒，number；用于显示提交与最近更新时刻。

pollAfterSeconds

建议下次查询间隔：进行中为 5，终态为 0。查询失败可退避；调用方等待超时不等于任务失败。

error

部署失败或待恢复的中文安全诊断对象；无错误时为 null。不包含密钥或原始日志。

active / url

仅该成功版本仍为当前在线版本时 active=true 且 url 非空。历史成功不等于现在在线。

3. B 端接口与已受理授权

POST /api/v1/integrations/deployments：Bearer 是专用来源凭证，必须显式签发 --kind source --all-apps --delegation-source project-a。请求 envelope 包含 deployment，并且 sessionId 或 receipt 二选一。直接请求带 sessionId 时 B 实时读 Redis；普通 personal/source Token 不自动获得代理用户的权限。 绑定 delegation_source 的凭证调用普通 /api/v1/automation 接口返回 403；普通自动化接口只接受未绑定委托来源的凭证，不可用其绕开共享用户身份。

推荐由已提供的 A 适配服务生成 receipt。它在受理时校验 Redis，事务保存完整部署内容、申请人、请求 ID 和 HMAC 签名受理凭据。后台向 B 发送 {"deployment":{...},"receipt":{...}}。B 校验来源、签名、请求内容、身份命名空间和本地权限，不要求用户此时仍保持登录。receipt 不是飞书 Token，但属于授权材料，必须保存在受限数据库，不能上传飞书表格、前端或普通日志。不要手工构造或修改 receipt，复用组件。

B 返回 HTTP 202 和任务视图。GET /api/v1/integrations/deployments/{jobId} 使用同一来源的有效委托凭证查询最新任务状态，返回 status、statusLabel、phase、phaseLabel、terminal、updatedAt、pollAfterSeconds、active、url、error 等；不需要用户仍登录，也不需要在 URL 传会话。相同来源可用轮换后的有效委托凭证查询和重投同一请求，仍返回原任务。不同来源不能查询；同一来源同请求 ID 不允许换申请人或请求内容。原凭证撤销会阻止其绑定的待执行任务；轮换应先把待投递/未完成请求切到新凭证并用原请求 ID 重放，再撤销旧凭证。签名密钥在待处理请求完成前不能直接换掉，否则旧 receipt 无法核验。

申请人首次从 A 接入时 B 创建普通成员，不授予管理员角色。既有账号保留本地禁用状态、权限和角色；A 不能传角色覆盖。会话退出不取消已受理任务，明确禁用账号、撤销来源或撤销应用权限仍会阻止未获执行授权的操作。

项目归属与任务提交人分别记录。新建项目的负责人是实际申请用户；更新已有 appId 时保留原项目负责人和归属，本次部署任务的提交人记录当前实际用户。指定后端、来源凭证负责人、管理员代为更新，都不会使原项目自动转归他们。更新必须通过当前用户的项目部署权限校验，不能仅凭搜索得到 appId 就越权更新。

4. 故障、存储和飞书记录

A 适配服务在 SQLite 事务提交后才返回 202。B 不可达、响应丢失或 5xx 时，后台按原 ID 持续退避重试（单次间隔逐步增加至 256 秒，并非总等待期限）；POST 400/403/409/422 作为明确拒绝，不无限重试。401 可能是来源凭证过期或需维护，保留请求并重试，不换 ID。Redis 不可用时不受理新的共享身份申请，返回 503；已经保存 receipt 的请求仍可继续投递。退出登录、会话过期和 Redis 清空都不会清除已提交数据库记录。

本机 SQLite 为 A 的待投递底账；B 数据库为部署状态权威。当前共享会话方案不会把 receipt 或会话写入多维表格；B 收件后，原有“应用”“部署记录”两表异步同步。应用表的负责人按项目现有 owner 记录：新建时是实际申请用户，更新时保留原负责人；部署记录的提交人按本次实际用户记录。不能把两者统一覆盖为来源凭证负责人或本次操作人。旧独立接入模块的“部署请求”表备份恢复是另一套接口，未自动接入本方案，不能声称新链路在 B 收件前已同步飞书或可以从该表恢复。若需要跨机器故障恢复，应备份 A 数据库、B 数据库及签名密钥，或单独扩展外部请求留痕。

A/B/Redis 暂时同机，因此 B 进程故障可由 A 保留请求，整机停机仍会影响两者。Redis AOF everysec 可能丢失故障前约一秒的会话写入，用户可重新登录；部署请求以 SQLite 记录为准。当前不承诺吞吐量或并发执行扩容。

5. 运维交接和迁移

配置示例：ops/team-sessions.example.json、ops/team-intake.example.json；服务：awesome-team-redis.service、awesome-team-intake.service。A 侧路径 /etc/awesome-team、/var/lib/awesome-team/requests.sqlite3；B 侧 /etc/awesome-deploy/team/sessions.json，平台配置 shared_sessions_file 指向它。只有受控服务账号可读密钥。

配置中的 source 必须与 registry 和委托来源凭证一致，为 1–40 位小写字母、数字或中划线，首位为字母或数字；registry 最多 32 个来源且不可重名。shared_sessions_file、database_path、platform_token_file、intake_token_file，以及 registry 的两个密钥文件，均使用非空绝对路径，不含控制字符。密钥文件按运行账号所有、0400/0600 权限保管；签名密钥至少 32 字节。

feishu_app_id 使用 cli_ 后接 1–80 位 ASCII 字母或数字，示例 cli_REPLACE 必须换成真实 App ID；tenant_key 使用 1–128 位 ASCII 字母、数字、下划线或中划线。两者必须与 B 相同。redis_username 为不含空白的非空可打印 ASCII 名称，A/B 可以使用各自的 ACL 用户；redis_url 不内嵌账号或密码，不能带查询参数或片段，数据库路径为 /0 至 /99，实际可用库数由 Redis 配置决定。显式端口为 1–65535。

同组 platform_origin 只允许 HTTPS 根地址，或 127.0.0.1、localhost、::1 的本机 HTTP 根地址；独立旧 intake 模块仍要求 HTTPS。地址不能包含 URL 用户名/密码、查询参数、片段、子路径、空白或反斜杠。platform_host 配置项可填 null；设置时只填不带协议、端口和路径的 ASCII 主机名。来源、路径或 URL 配错时会在启动加载配置阶段拒绝，不能把启动失败当成部署请求已受理。

Redis 本机专用端口 6391，64 MiB 内存上限，noeviction；A ACL 仅可操作 project-a 会话键的 GET/SET/DEL，B ACL 只可 GET。默认账号禁用，不开放公网。未来迁到异机时，把两侧 registry 的 redis_url 改为 rediss://目标主机:端口/0，配有效 TLS 证书和分别的 ACL 密码文件；代码不允许远端明文 redis://。迁移前暂停会话写入/新申请，迁移数据或让用户重新登录，验证 A/B 指向同一 Redis 后恢复；已经落库的请求不依赖会话迁移。异机 Redis 不是 A/B 数据库备份。

平台来源凭证有效期 1–90 天，运维需到期前轮换。签发命令仅在可信终端执行，输出直接写入接入服务账号的 0600 文件，不复制到文档：

awesome-deploy --config /etc/awesome-deploy/config.json api-token-create \
  --user-id PLATFORM_RESPONSIBLE_USER_ID --name project-a --kind source \
  --all-apps --delegation-source project-a --days 90

6. 接入验收

□ A 自己验证 OAuth，或可信后端验证上游登录态后创建共享会话；不采信浏览器传来的身份、角色，不复制 Cookie、密码或飞书 Token；退出后新请求被拒绝。 □ Alice、Bob 各自搜索和部署：不能看到或更新对方未授权的项目；授予 maintainer 后可搜索并更新，原 owner 不变，本次 submitter 正确。普通凭证不能委托。 □ B 不可达时 A 返回持久请求 ID；恢复后取得 jobId/appId。 □ B 已接收但响应丢失时，同 ID 重试只有一个任务；重启 A 适配服务继续投递。 □ 已受理后退出登录仍能部署；本地停用、来源撤销和权限撤销按平台授权规则生效。 □ 管理员 can_deploy=true 时可搜索全部；can_deploy=false 时被拒绝。指定后端使用普通用户 sessionId 时仍受该用户权限限制，items 和 total 均不泄露其他项目。 □ 搜索遗漏或失效 sessionId 时被拒绝；A 查询前端请求进度时检查 requestId 属于当前用户，或具有该项目的部署详情读取权限（admin、owner、maintainer；仅 viewer 不足），不能只因内部来源 Token 有效就返回他人请求。 □ 请求最终状态、错误摘要、在线链接可显示，凭证和 receipt 不出现在网页及飞书表格。 □ Redis 外部端口不可达，A/B ACL 不越权；迁移与数据库备份分开验收。

完整接口定义见 API 参考文档：第 2 章说明共享登录态、搜索权限和部署归属，第 3 章提供同组接入服务的搜索、提交、进度和登录同步接口，第 4 章列出平台同组部署接口。各接口均有参数表和请求、响应示例。控制台管理接口在第 6—9 章，使用平台网页登录认证。仓库要求见 部署接入技术协议 v2.0；网页操作见 平台使用手册。
