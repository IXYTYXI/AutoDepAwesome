Awesome Deploy｜API 接口总手册

适用平台 0.11.2；核对日期 2026-10-23。本手册汇总 B 部署平台和当前 A 同组适配服务的全部显式 HTTP 路由，统一说明认证、权限、请求、返回与错误。原 API 手册链接保持不变。第 3—4 章供调用方直接接入，第 5—8 章供控制台开发与管理集成查阅，第 9—10 章列出登录、页面资源与旧版模块。

202 表示受理，不表示上线成功。共享登录态决定实际用户，来源凭证只证明调用服务；不能借用凭证负责人的管理员权限。秘密值只能保存在后端受控配置中，不能放入浏览器、Git 或示例文件。

仓库、awesome.yaml、Dockerfile 与运行限制：部署接入技术协议 v2.0

1. 地址、认证与权限

入口

地址与使用方式

B 部署平台

https://awesome.guanghexinzhi.cn；本手册 /api/v1/ 和 /auth/ 路径均在 B。

A 同组适配服务

当前 http://127.0.0.1:8099，只供同机可信后端。/sessions、/apps/search、/requests 都在 A。浏览器不能直连。

当前交付边界

A 适配组件已部署；具体上游 A 业务项目尚待接入。Redis 存会话，SQLite 存请求。当前 Redis 在本机，后续可通过受控网络与 TLS 迁移。

线上接口定义

GET /api/v1/openapi.json 需要控制台登录，包含 B 路由；不包含独立 A 路由。默认 /docs、/redoc、/openapi.json 关闭。鉴权和部分动态返回以本文与对应实现为准。

文中标记 / 凭证

用于哪些接口

C：控制台 Cookie

网页登录后的平台会话；用于 /api/v1/deployments、apps、management、密钥、成员等控制台接口。API Bearer 不能替代。

W：控制台写请求

在 C 基础上加 Origin: https://awesome.guanghexinzhi.cn、X-CSRF-Token（从 /auth/session 取）及 Content-Type: application/json；DELETE 也需要。

F：近期认证

敏感管理操作须在最近 600 秒完成飞书登录，否则 AUTH_REAUTH_REQUIRED；重新登录后再取当前 csrfToken。

普通 automation Bearer

个人凭证或普通来源凭证，调用第 3 章两项接口。实际操作身份为凭证绑定成员；受凭证范围及成员当前权限约束。

同组 B 专用 Bearer

运维登记的 kind=source、allowAnyApp=true、delegation_source 来源凭证，调用 integrations 接口；不是普通个人 Token。

A 内部 Bearer

调用 8099 适配服务；与 B 专用凭证不同。仅存在 A 可信后端，不能交给用户浏览器；A 拒绝带 Origin 或 Sec-Fetch-Site 的请求。

sessionId

A 验证上游真实登录后签发的共享会话 ID。B 按它识别用户与有效期；不是飞书 OAuth Token，也不是浏览器 Cookie。

普通用户能用 API 部署，也能通过同组共享会话搜索自己的或已授权维护的项目。管理员能搜索全部项目；viewer 不具备部署搜索权限。所有部署和部署搜索均要求账号有效且 canDeploy=true。后台服务持有管理员负责的 Token，不会使普通申请人变成管理员。

新建项目负责人是实际申请人；更新保留项目原负责人，本次部署的提交人记录为实际操作人。普通 automation 按凭证绑定成员执行，同组 integrations 按共享身份执行。请求 JSON 不允许指定 owner、role 或 userId 来冒充其他身份。

GET 用于读取，POST 用于提交部署、复杂搜索和受控操作；PUT/PATCH/DELETE 用于对应管理修改。没有“全部改用 POST”的要求。当前没有 /api/v1/automation/apps/search；个人 Token 不能直接调用 integrations 搜索。

同组内部进度 GET 按来源授权，不携带 sessionId。A 将查询结果展示给浏览器前，必须检查当前用户是该请求申请人或拥有项目详情权限（管理员、owner、maintainer）。知道 requestId、jobId 或 appId 不构成授权。

2. 通用请求与返回结构

2.1 Deployment：创建和更新共用

字段

约束与含义

repository

必填 string。允许列表内 GitHub/GitLab HTTPS 仓库，最长 2048 字符；不接受 URL 中嵌入凭证、端口、查询串或 fragment；规范化后补 .git。

subdomain

必填 string，页面称“项目名称”。1–7 位小写字母、数字或中划线，首尾为字母或数字；不含中文、空格、大写，避开保留名；必须与仓库 awesome.yaml 的 app.subdomain 一致。

ref

可选 string，默认 main。可指定真实分支、标签或完整 commit；1–200 字符，仅字母数字及 . _ / -，以字母数字开头；不接受 ..、//、尾 /、尾 .、点开头路径段、.lock 后缀或 Git 表达式。

appId

创建省略；更新必填已有应用 ID，[A-Za-z0-9_-]{1,64}。B 接受 null 表示创建；A 中有此字段时必须是非空字符串，所以新建统一省略。

更新约束

repository 必须与原应用一致；已绑定域名时 subdomain 必须保持一致。保留数据下线后可选择新的空闲名称，但必须与新清单一致。更新不转移负责人。

其他字段

拒绝未知字段；不要添加密码、Token、环境变量或用户角色。分支内容与构建文件须提前推送到 Git。

请求体统一为 JSON。B 请求体总上限 128 KiB；严格类型字段不做字符串/数字/布尔自动转换。Idempotency-Key 为 1–128 位字母、数字、点、下划线、冒号或中划线。每次新部署先生成并保存新键；网络重试复用原键、原内容和原身份。

queued / running 继续按 pollAfterSeconds 查询；succeeded / failed / recovery_required / cancelled 为终态。terminal=true 不一定成功。只有 succeeded 且 active=true 才说明该次版本当前在线；后续更新或下线后，历史成功任务可能 active=false、url=null。阶段没有固定耗时，不提供百分比、预计完成时间或队列名次。

PublicJob 不直接返回申请人 userId；归属记录在平台数据库及登记流程中。error 为 null 或安全中文诊断对象，含 code、title、message、path、suggestion、steps，可选 reason；不返回原始日志或密钥。

2.3 RequestEnvelope：A 的持久受理记录

字段

约束与含义

requestId

原Idempotency-Key

status

pending|submitted|succeeded|failed|recovery_required|cancelled|rejected

jobId

null直到B受理

appId

null直到B受理

error

null或投递错误string；业务失败看deployment.error

createdAt

A记录创建时间Unix秒

updatedAt

A记录处理时间Unix秒，不能作为B状态新鲜度

外层终态/rejected为0，其余5

A 的 202 表示 SQLite 事务已经提交，此时 jobId/appId/deployment 仍可能为 null。pending 是等待投递，submitted 是 B 已受理，rejected 是投递被终止；业务执行状态看 deployment.status。deployment 是最近同步快照，终态后不持续刷新后续下线信息；要确认当前在线版本，可由受信后端读取 B 的同组任务 GET。

3. 普通自动化 API：脚本、CI 与个人后端

在控制台“API 凭证”页通过飞书登录创建个人凭证。范围三选一：我有权部署的应用、指定单个应用、仅创建新应用；默认 30 天，可设 1–90 天。完整 token 只返回一次，将其放入后端密钥配置并注入 AWESOME_DEPLOY_TOKEN。同一 Token 可多次部署；没有“一枚 Token 只能部署一次”的限制。具名来源凭证由管理员/运维另行签发，不使用个人凭证 HTTP 创建接口。

方法与路径

请求 / 成功返回

权限与幂等

POST /api/v1/automation/deployments

Bearer + application/json + Idempotency-Key；体为 Deployment；202 Job。

凭证范围与其负责人当前部署权限均须通过。同一身份+同一 credential_id+同键+相同规范化内容返回原任务；改内容 409。

GET /api/v1/automation/deployments/{job_id}

Bearer；无请求体；200 Job。

必须是提交时同一有效 credential_id，并仍有任务详情权限。同一账号新建另一枚 Token 不能自动查询旧任务。

首次部署示例：在受控后端环境注入凭证，将 REQ_ID 设置为已在业务数据库保存的稳定申请 ID；示例不会自动生成每次不同的键。创建不填 appId，ref 省略即 main。

# token只由后端安全环境注入；REQ_ID先由业务数据库保存。此示例不执行。
curl --fail-with-body --silent --show-error \
  -X POST https://awesome.guanghexinzhi.cn/api/v1/automation/deployments \
  -H "Authorization: Bearer $AWESOME_DEPLOY_TOKEN" \
  -H "Idempotency-Key: $REQ_ID" -H 'Content-Type: application/json' \
  --data '{"repository":"https://github.com/your-org/your-repo.git","subdomain":"demo"}'
# 202响应中的id保存为JOB_ID，再用同一Token GET：
curl --fail-with-body --silent --show-error \
  -H "Authorization: Bearer $AWESOME_DEPLOY_TOKEN" \
  "https://awesome.guanghexinzhi.cn/api/v1/automation/deployments/$JOB_ID"

更新仍使用同一个 POST，唯一变化是加入已取得的 appId；新的一次更新用新幂等键。只能创建新应用的凭证不能用于更新。

{
  "repository": "https://github.com/your-org/your-repo.git",
  "subdomain": "demo",
  "appId": "example-app-id"
}

HTTP 202 后保存 id 与 appId，按第 2 章轮询到终态。请求超时不代表平台没收到：保留原请求与幂等键，查询原任务或用同一凭证重试。同组继承用户登录的项目请使用下一章链路，不能用来源负责人身份代替真实申请人。

4. 同组接入：共享登录、搜索、更新与进度

上游业务 A 先验证自己的登录，再将可信身份登记到共享会话；适配服务先保存申请，后台用专用来源凭证投递 B。sessionId 保存在 A 的服务端会话映射中；不复制用户密码、Cookie 或飞书 access_token 给 B。身份必须使用 B 已配置的同一飞书 App 与 tenantKey 下的 openId，不按姓名猜测，也不从前端传入管理员角色。

默认共享会话为 8 小时绝对有效期，无滑动续期；实际 ttl 应取上游剩余登录有效期与 28800 秒的较小值。Redis 故障时不能签发会话、搜索或受理新申请；已入库的受理记录可依靠签名凭据继续投递。B 若以后需要代用户操作飞书业务接口，须另做相应 OAuth 授权；共享身份本身不包含该授权。

4.1 A 适配服务接口（当前 8099）

方法与路径

JSON 请求 / 成功返回

约束

POST /sessions

{identity:{appId,tenantKey,openId,name},ttl?:28800} → 201 {sessionId,expiresIn}

内部 Bearer；identity 必须取自已验证上游登录。ttl 为 1–28800 整数；name 为 1–256 字符且无控制字符。体 ≤4096 字节。

POST /sessions/revoke

{sessionId} → 200 {revoked:true}

内部 Bearer；上游退出时调用。Redis 不可用返回 503，不应伪装退出成功；已受理任务继续投递。

POST /apps/search

Search 请求见下表 → 200 SearchResult

内部 Bearer；不需要幂等键；实时查询，不写申请数据库；体 ≤4096 字节。失败不能伪装为零条结果。

POST /requests

{sessionId,deployment:Deployment} + Idempotency-Key → 202 RequestEnvelope

内部 Bearer；体 ≤16384 字节；先验证共享会话、生成受理凭据并提交 SQLite 事务。相同 ID 改内容或申请人 409。

GET /requests/{request_id}

无请求体 → 200 RequestEnvelope；不存在 404

内部 Bearer；按来源访问，不带 sessionId。A 网页层必须另做用户归属或项目详情权限检查。

以上 POST 都使用 Content-Type: application/json。A 业务后端不自行构造 receipt。当前 /requests 必须包裹 deployment 与 sessionId，不能发送平铺 repository/subdomain，也不能直接让浏览器带内部 Bearer 请求。

4.2 Search 与 SearchResult

字段

约束与含义

sessionId

必填 string，有效共享会话。不接受 receipt 代替；凭证负责人为管理员不提升此用户权限。

query

可选 string，默认空，最多 200 字符。trim 后忽略大小写，包含匹配当前/历史项目名称、仓库地址或 appId。

limit / offset

可选严格整数。limit 默认 20，范围 1–20；offset 默认 0，范围 0–1000000；布尔值不算整数。

items

数组。每项只含 appId、projectName、repository、subdomain、lastSubdomain、domainBound；名称或历史名称可能为 null。

total / limit / offset / nextOffset

total 是按实际用户权限及关键字过滤后的数量；先授权后分页。nextOffset 为下一页偏移，无下一页为 null。空结果为 items=[]、total=0。

搜索范围

账号有效且 canDeploy=true：普通用户的 owner/maintainer 项目；本地管理员全部项目；viewer 不返回。

4.3 B 同组接口（由 A 适配服务调用）

方法与路径

JSON 请求 / 成功返回

权限与幂等

POST /api/v1/integrations/apps/search

Search → 200 SearchResult；application/json；无需幂等键。

专用委托来源 Bearer + 有效 sessionId；真实用户范围见 4.2。Redis 不可用 503。

POST /api/v1/integrations/deployments

{deployment:Deployment,sessionId} 或 {deployment:Deployment,receipt}；application/json + Idempotency-Key → 202 Job。

sessionId/receipt 严格二选一。receipt 仅由可信 A 组件生成，绑定来源、申请人、请求 ID 与内容。来源+请求 ID 构成稳定幂等域；改内容或申请人拒绝。

GET /api/v1/integrations/deployments/{job_id}

无请求体 → 200 Job。

同一 delegation_source 有效来源 Bearer 可查询；允许同源轮换后的凭证，不需要 sessionId。A 展示给用户前仍须另做权限过滤。

B 每次受理及执行继续检查本地账号与应用权限，不把上游角色导入成平台管理员。新项目归实际共享身份用户，更新不改原负责人。来源可提交多个项目和多次任务，但应用硬配额、授权、队列并发限制仍然生效。

4.4 同组端到端接入示例（Python）

此示例运行在可信 A 业务后端，依赖 httpx。AWESOME_TEAM_INTAKE_TOKEN 来自安全配置；verified_identity 来自经过验证的真实登录。请求 ID 必须先由 A 业务数据库生成和保存，所有重试复用。代码包含新建、分页搜索、按用户选定 appId 更新、查询进度与退出；不是可直接嵌入浏览器的代码。

# 运行在 A 的可信后端。identity 来自已验证的上游登录服务，不取浏览器 JSON。
# 所有 request_id 都由 A 业务数据库首次生成并保存；同次重试复用，不能每次生成。
import os
import time
import httpx

client = httpx.Client(base_url="http://127.0.0.1:8099",
    headers={"Authorization": "Bearer " + os.environ["AWESOME_TEAM_INTAKE_TOKEN"]},
    timeout=15, trust_env=False, follow_redirects=False)

def call(method, path, **kw):
    response = client.request(method, path, **kw)
    response.raise_for_status()  # A 应统一提取 error.message/detail；勿输出headers、session或receipt。
    return response.json()

def share_login(verified_identity, remaining_login_seconds):
    return call("POST", "/sessions", json={"identity": verified_identity,
        "ttl": min(28800, remaining_login_seconds)})["sessionId"]

def submit(session_id, request_id, deployment):
    return call("POST", "/requests", headers={"Idempotency-Key": request_id},
        json={"sessionId": session_id, "deployment": deployment})

def progress(request_id, wait_seconds=600):
    # 调用本函数之前，A 必须检查请求本人或应用 detail 权限，不能相信前端任意 request_id。
    deadline = time.monotonic() + wait_seconds
    while time.monotonic() < deadline:
        value = call("GET", "/requests/" + request_id)
        deployment = value["deployment"]
        if value["status"] == "rejected":
            return value  # 展示外层 error；不要自动用新 ID 重提。
        if deployment is not None and deployment["terminal"]:
            return value  # terminal 不等于成功，检查 deployment.status/error。
        time.sleep(max(1, value["pollAfterSeconds"]))
    raise TimeoutError("本次等待结束；保留原 requestId，稍后继续 GET，不能据此判定部署失败")

def search(session_id, query):
    offset = 0
    found = []
    while True:
        page = call("POST", "/apps/search", json={"sessionId": session_id,
            "query": query, "limit": 20, "offset": offset})
        found.extend(page["items"])
        if page["nextOffset"] is None:
            return found
        offset = page["nextOffset"]

def create_project(session_id, persisted_request_id, repository, project_name):
    # repository 需包含符合技术协议的 awesome.yaml；ref 省略即 main。
    return submit(session_id, persisted_request_id,
        {"repository": repository, "subdomain": project_name})

def update_project(session_id, persisted_request_id, query, selected_app_id, new_project_name=None):
    # selected_app_id 必须经用户选择；不能取搜索第一项。
    matches = [a for a in search(session_id, query) if a["appId"] == selected_app_id]
    if len(matches) != 1:
        raise ValueError("项目不存在、匹配不唯一或当前用户无部署权限")
    app = matches[0]
    name = app["subdomain"] if app["domainBound"] else new_project_name
    if not name:
        raise ValueError("原项目未绑定域名，请选择与 awesome.yaml 一致的空闲项目名称")
    return submit(session_id, persisted_request_id,
        {"appId": app["appId"], "repository": app["repository"], "subdomain": name})

def logout(session_id):
    return call("POST", "/sessions/revoke", json={"sessionId": session_id})

# A 回调：sid = share_login(verified_identity, remaining_login_seconds)
# 把sid关联A服务端会话，不能给浏览器保管。
# 新建：accepted = create_project(sid, saved_new_id, repo, name); result = progress(accepted["requestId"])
# 更新：先search给用户选择；accepted = update_project(sid, saved_update_id, query, selected_id); result = progress(accepted["requestId"])
# 异常处理后可再 GET 原 requestId；POST超时只能用原requestId和原内容重试。

接入顺序：登录回调签发共享会话并关联本地服务端会话 → 搜索供用户选定 appId → 保存申请 ID 与申请人关联 → 提交 /requests → 保存返回 requestId/jobId/appId → GET 进度并展示 deployment.status/phaseLabel/error。轮询等待超时仅结束本次等待，保留 ID 以后继续查；不要据此新建申请。

A 事务入库后才返回 202。B 暂时不可达或响应丢失时，A 用同 ID 后台重投；POST 400/403/409/422 结束为 rejected，401/网络/5xx 保留记录退避重试。已受理请求不因共享会话退出而丢失。A、B 同机时整机故障仍需要异机备份，Redis 不替代请求数据库。

B 收件后异步同步应用主表和部署记录表；飞书同步不阻塞部署。当前同组链路没有接入旧独立模块的“部署请求表恢复”，不能宣称 B 完全没收到时已自动在飞书留档。签名受理凭据、sessionId、Token 和秘密值不写飞书表格。

7.1 GET /api/v1/deployments/{job_id}/secrets

认证与权限：C；管理员/owner/maintainer + canDeploy。

请求：无请求体；除已列出的路径参数外，无业务查询参数。

成功：HTTP 200；DeploymentSecretRequirements。

仅失败且 error.code=SECRET_NOT_FOUND、固定快照可核验、数据未清除的任务；其他 409 SECRET_CONFIGURATION_NOT_AVAILABLE。不返回密钥值。

认证与权限：C+W；管理员/owner/maintainer + canDeploy。

7.3 GET /api/v1/apps/{app_id}/secrets

认证与权限：C；管理员/owner/maintainer + canDeploy；仅 Feishu + encrypted，否则404。

请求：无请求体；除已列出的路径参数外，无业务查询参数。

成功：HTTP 200；{appId,items:[SecretMetadata],operations:[SecretRevocationOperation],can_rotate:true,can_revoke:<owner/admin>}。

只返回元数据及版本，绝不返回 secret value；SecretMetadata={name,kind,current_version,data_generation,versions:[{version,status}]}。

7.4 POST /api/v1/apps/{app_id}/secrets/{name}/rotate

认证与权限：C+W；管理员/owner/maintainer + canDeploy；Feishu+encrypted；F（最近 10 分钟登录）。

请求：JSON 请求体采用 SecretRotationRequest（字段见第 8 章）；路径参数：name 匹配 [A-Za-z][A-Za-z0-9_-]{0,63}。

成功：HTTP 200；{name,current_version}。

只允许 kind=runtime_secret；平台数据主密钥禁止普通轮换。expected_current_version 为32位小写hex，CAS 冲突 409。下线/销毁期间阻止。轮换不自动部署，已固定旧版本的部署不自动变更。

7.5 POST /api/v1/apps/{app_id}/secrets/{name}/revoke

认证与权限：C+W；管理员/owner + canDeploy；Feishu+encrypted；F（最近 10 分钟登录）。

请求：JSON 请求体采用 SecretRevocationRequest（字段见第 8 章）；路径参数：name 匹配 [A-Za-z][A-Za-z0-9_-]{0,63}。

成功：HTTP 202；SecretRevocationOperation。

只允许 runtime_secret；version/expected_current_version 均32位小写hex；reason 单行1–1024字符不得CR/LF/NUL。吊销是异步操作；随后 GET 应用 secrets 的 operations 观察，不存在单独 revocation GET。会触发受影响版本的处置，不能描述成单纯删除一行配置。

DeploymentSecretRequirements：jobId、repository、subdomain、canGenerate、items。每项为 {name,uses:[{service,environmentVariable}],state,managed}，state 为 missing/configured/unavailable；不返回秘密值。保存缺失配置之后，使用新幂等键提交新的部署，并带回原 appId。

SecretMetadata：name、kind、current_version、data_generation、versions:[{version,status}]。SecretRevocationOperation：id、app_id、name、version、status、error、created_at、updated_at；状态 queued/running/recovery_required/succeeded。这些接口确实使用 snake_case，不要改成 camelCase；没有单独的吊销进度 GET，查看 GET 应用 secrets 的 operations。

控制台同源 JavaScript 调用范式如下。只在已登录的 Awesome Deploy 控制台 origin 执行；其他网页后端应使用第 3 或 4 章，不复制平台 Cookie。示例预校验不创建部署，不含秘密值。

const sessionResponse = await fetch('/auth/session', {credentials: 'same-origin'});
if (!sessionResponse.ok) throw new Error('请先登录');
const session = await sessionResponse.json();
const response = await fetch('/api/v1/preflight', {
  method: 'POST', credentials: 'same-origin',
  headers: {'Content-Type': 'application/json', 'X-CSRF-Token': session.csrfToken},
  body: JSON.stringify({manifest: yamlText}) // yamlText 是用户提供的完整清单文本
}); // 浏览器自动发送同源 Origin，不要尝试在 JS 中伪造。
const result = await response.json();
if (!response.ok) throw new Error(result.error?.message || result.detail || '请求失败');
// result.scope === 'configuration_only'，不代表完成部署。

9. 登录、会话与网页资源路由

平台 Cookie 绝对有效期 8 小时、闲置 30 分钟过期；与 A 共享会话的绝对 TTL 是两套机制。当前使用飞书模式。旧 HTTP Basic 模式仅为兼容，不作为新接入方案。

9.1 GET /auth/feishu/start

无；仅 Feishu 模式；否则 404。

请求：{"query": {"return": "可选，默认 /；允许本地页面白名单，非法值回退 /"}}

成功：303 跳转飞书授权 URL；设置 300 秒的 PKCE/OAuth 浏览器绑定 Cookie。

return 实际白名单：/, /manage, /members, /document, /api-access；/document?doc=overview|api|protocol|protocol-legacy|audit。当前 intake/catalog 不在 begin_login 的 doc 子白名单，勿承诺这些登录后精确回跳。

9.2 GET /auth/feishu/callback

OAuth 一次性 state + 浏览器绑定 Cookie + code，PKCE；仅 Feishu 模式；否则 404。

请求：{"query": {"state": "required OAuth state", "code": "正常成功回调 required；1–4096 可打印 ASCII 非空白字符", "error": "提供则视为取消授权；state/code/error 重复参数拒绝"}}

成功：303 成功跳转已验证 return 并设置会话 Cookie；失败跳 /login?error=cancelled|invalid|expired|denied|unavailable；清除 OAuth Cookie。

集成方不应自行生成 code/state 或复制飞书 token 作为平台 Cookie。

9.3 GET /auth/session

控制台认证：Feishu Cookie（或配置为 Basic 模式时 HTTP Basic）；不能用 API Bearer 替代。

成功：{mode,authenticated,userId,displayName,role:admin|member,canDeploy,csrfToken,capabilities:{vault_enabled}}；Basic 模式省略 userId/displayName/csrfToken。

csrfToken 取此接口；平台 Cookie 绝对有效期 8 小时、闲置 30 分钟过期。

9.4 POST /auth/logout

控制台写认证：C + 精确 Origin + X-CSRF-Token + application/json；非 Feishu 的 Basic 模式免 CSRF 但仍检查 Origin/cross-site/content-type；仅 Feishu 模式；否则 404。

请求：{"body": "无模型字段；仍须 Content-Type: application/json，推荐 {}"}

成功：{ok:true}；撤销当前平台 Cookie 并删除 Cookie。

11. 错误、重试与接入验收

HTTP / 现象

调用方处理

200 / 201 / 202

200 成功读取/操作；201 创建会话或凭证；202 仅受理异步任务。继续查询任务或操作状态。

400

请求体或 Idempotency-Key 等基础格式错误。

401

凭证/会话缺失、过期或撤销；A /requests 的部分字段校验目前也可能返回 401，需读 detail，不要一律提示密码错误。

403

用户、应用、来源或范围无权；AUTH_REAUTH_REQUIRED 表示重新飞书登录后再执行敏感操作。

404

资源不存在、路径错误或该能力未启用；不要把 appId、jobId、requestId 混用。

409

幂等内容冲突、应用/域名占用、版本变更或当前状态不允许；根据 error.code 处理，不要换键盲重试。

413 / 415 / 422

体积过大 / 非 application/json / 字段、类型、部署参数或配置校验失败。

429

认证或 AI 等相关接口忙/限流；遵循返回提示退避。

503 / 504

依赖或 AI 服务不可用 / AI 超时；部署是否受理须按原 ID 查，不依据 HTTP 错误推断已清理。

网络超时或响应丢失

不能确定服务器是否已经受理；保存原 ID、内容、身份，查询或同键重试。不得每次换键造成重复上线。

B 错误可能为 {detail:中文字符串}，也可能为 {error:{code,title,message,path,suggestion,steps,reason?}}；A HTTP 错误主要为 {detail:中文字符串}。调用方两种都要识别。HTTP 成功与任务状态分开判断：GET 返回 200 的 Job 仍可能是 failed。不要将响应对象、请求头、sessionId 或 receipt 原样写日志。

{
  "error": {
    "code": "INVALID_REQUEST",
    "title": "请求参数无效",
    "message": "请检查请求字段。",
    "path": "request",
    "suggestion": "按接口字段约束修改后再提交。",
    "steps": [
      "按接口字段约束修改后再提交。"
    ]
  }
}

上面的诊断对象仅展示结构；具体 code、title、path 取实际响应，不以示例字符串匹配业务。幂等域不同：普通 automation 绑定确切凭证；同组绑定 delegation_source + requestId。凭证轮换前应处理未完成请求，普通 Token 更换不能自动接管旧 Token 查询。

接入验收至少覆盖：真实用户登录签发与退出；普通用户只搜自己的或授权项目、管理员全量搜索、viewer 不可部署；选定 appId 更新且负责人不变；202 后 queued/running 到终态；同 ID 重试不重复部署；会话失效或 Redis/B 不可用时返回明确错误；A 给浏览器查进度时校验归属；秘密值不进入日志、前端或飞书表。

本手册按当前源代码的 52 个显式运行路由核对：B 47 项（含登录、页面和静态资源）+ A 5 项；另单列旧独立模块的 2 项请求路由。未提供暂停/取消部署、调整队列顺序、SSE/WebSocket 进度推送或 Bearer 下线管理接口，不应自行假设存在。
