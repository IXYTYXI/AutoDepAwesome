Awesome Deploy｜自动化部署 API 使用手册

这份手册面向需要从脚本、CI 或指定请求源提交部署的人。日常操作先用飞书登录平台；API 凭证仅用于提交部署和查询由该凭证创建的任务。

最重要的两点：HTTP 202 只表示任务已进入队列，不表示上线成功。完整凭证只显示一次，不要写进 Git 仓库、请求文件或聊天消息。

1. 取得 API 凭证

打开 API 凭证页面，使用飞书登录。在“创建个人凭证”中填写名称、部署范围和有效期；创建时需要最近 10 分钟内的登录确认。凭证有效期为 1–90 天，默认 30 天。

范围可选“我有权部署的应用”（可创建新应用并更新当前有权限的应用）、“指定单个应用”（只能更新该应用）、“仅创建新应用”。创建后立即复制完整凭证，存入调用程序的密钥配置，并以环境变量 AWESOME_DEPLOY_TOKEN 注入。页面之后只能查看凭证名称、范围和有效期，不能再次查看完整值。

少数具名自动化来源由平台管理员单独签发和撤销，并关联一位负责的飞书成员。来源可连续提交多个应用和任务；队列、权限及资源配额照常生效。

2. 首次部署

先在调用程序的工作目录创建 deployment.json。下面的仓库、分支和域名前缀都要换成真实值。仓库中还必须有符合 平台使用手册 要求的 awesome.yaml。

{
  "repository": "https://github.com/your-org/your-repo.git",
  "ref": "main",
  "subdomain": "demo"
}

确认运行环境已经从安全配置注入 AWESOME_DEPLOY_TOKEN 后，提交请求。每次新的部署都要使用新的 Idempotency-Key；示例键只用于演示。

curl --fail-with-body -sS \
  -H "Authorization: Bearer ${AWESOME_DEPLOY_TOKEN}" \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: demo-initial-001' \
  --data-binary @deployment.json \
  https://awesome.guanghexinzhi.cn/api/v1/automation/deployments

成功受理时返回 HTTP 202，响应包含任务编号 id 和应用编号 appId。请保存 id 供后续查询。此时任务可能仍在排队。

3. 查询任务结果

把下面的 JOB_ID 换成提交响应中的 id。查询必须使用提交该任务的同一枚凭证；其他凭证不能读取这条任务。

curl --fail-with-body -sS \
  -H "Authorization: Bearer ${AWESOME_DEPLOY_TOKEN}" \
  https://awesome.guanghexinzhi.cn/api/v1/automation/deployments/JOB_ID

status

含义与下一步

queued

已入队；稍后用同一接口查询。

running

正在执行；继续查询。

succeeded

该次部署成功；再看 active 和 url 确认它是否仍是当前在线版本。

failed

部署失败；查看响应中的中文 error，修复原因后用新幂等键重新提交。

recovery_required

需要平台管理员检查资源与恢复状态；不要把它当成成功。

4. 更新已有应用

更新时在请求体中加入已有应用的 appId，并保持 repository、subdomain 与该应用一致。可以更换 ref；提交时换用新的幂等键。应用编号可从首次提交响应或应用管理页取得。创建新应用时不要填写 appId。

{
  "repository": "https://github.com/your-org/your-repo.git",
  "ref": "main",
  "subdomain": "demo",
  "appId": "已有应用编号"
}

“指定单个应用”范围的凭证只能更新那一个应用；如果账号失去该应用的部署权限，凭证也不能继续部署它。

5. 重试与常见错误

如果提交请求发出后没有收到响应，使用相同请求体、相同凭证、相同幂等键重试；平台会返回同一任务。真正的新部署必须换键。同一幂等键对应不同请求会发生冲突。幂等键长度为 1–128，只能使用字母、数字、点、下划线、冒号和中划线。

HTTP 状态

先检查什么

401

Bearer 凭证是否填写、过期或已撤销；不要用网页登录 Cookie 代替。

403

凭证范围、负责人的部署权限及目标应用权限。

409

幂等键是否复用于不同请求，或应用、域名是否发生冲突。

422

JSON 字段、类型和格式是否符合接口要求。

API 凭证不能用于网页管理、修改密钥、管理成员或下线应用。撤销凭证后，调用方不能再提交或查询；尚未执行的关联部署也会失去授权。查看凭证或撤销凭证请回到 API 凭证页面。
