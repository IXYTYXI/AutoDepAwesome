个人自动化示例：先登录平台“API 凭证”页面创建凭证，把完整 Token 保存到调用后端的安全配置，并注入 AWESOME_DEPLOY_TOKEN。将仓库地址和项目名称替换为自己的值；该仓库的 main 分支应已具备有效 awesome.yaml。

curl --request POST \
  'https://awesome.guanghexinzhi.cn/api/v1/automation/deployments' \
  --header "Authorization: Bearer ${AWESOME_DEPLOY_TOKEN}" \
  --header 'Content-Type: application/json' \
  --header 'Idempotency-Key: deploy-20261023-001' \
  --data '{"repository":"https://github.com/your-org/your-repo.git","subdomain":"demo"}'

收到 HTTP 202 后，保存响应中的 id（部署任务 ID）。新建项目的 appId 初始可能为 null，后续查询得到非空值后再保存为项目 ID。用提交时同一枚凭证查询任务：

curl --request GET \
  'https://awesome.guanghexinzhi.cn/api/v1/automation/deployments/<JOB_ID>' \
  --header "Authorization: Bearer ${AWESOME_DEPLOY_TOKEN}"

按响应 pollAfterSeconds 间隔查询。terminal=true 后停止轮询，并检查 status：succeeded 为成功，failed 为失败，recovery_required 需要管理员处理。HTTP 202 和 GET 的 HTTP 200 都不等同于部署成功。

2. 认证与权限

2.1 API 凭证

个人 API 凭证在平台“API 凭证”页面创建，默认有效期 30 天，可设为 1–90 天。完整 Token 只显示一次。凭证可重复用于多次部署；范围选择“我有权部署的应用”“指定单个应用”或“仅创建新应用”。凭证范围和所属用户的当前权限同时生效。

同组接入使用两枚服务端凭证：业务后端持有接入服务凭证 INTAKE_TOKEN；接入服务持有平台来源凭证 SOURCE_TOKEN。由管理员为指定来源配置，不能用普通个人 Token 代替。它们均通过 Authorization: Bearer 发送，不交给浏览器。 从 0.11.3 起，绑定共享登录来源的凭证仅可调用同组委托接口；调用普通 /api/v1/automation 接口返回 403，不能借用凭证持有人的管理员身份。

同机调用可使用配套 Skill 的 Python 客户端，默认读取 /etc/awesome-team/intake-token；也可一次性配置 AWESOME_INTAKE_TOKEN 或 AWESOME_INTAKE_TOKEN_FILE。实际可用 Key 和配置示例见 同机服务 Key 与快速接入。

2.2 共享登录态与项目权限

业务后端验证用户真实登录后，调用 POST /sessions 建立共享会话，将返回的 sessionId 与自己的服务端登录会话关联。搜索、提交部署时携带该 sessionId。普通用户可搜索自己拥有或被授予 maintainer 权限的项目；管理员可搜索全部项目；viewer 无部署搜索权限。账号必须有效且允许部署。

新建项目负责人为实际登录用户；更新项目保留原负责人，本次部署的提交人记录为实际操作人。来源凭证只证明哪个服务发起请求，不赋予用户凭证负责人的管理员权限。不要传入角色或 userId 来替换真实登录身份。

同组内部进度查询按来源授权。业务后端向浏览器返回结果之前，必须检查当前用户是该请求申请人，或者拥有该项目的详情权限（管理员、owner、maintainer）。知道任务 ID 不代表有权限查看。

2.3 控制台接口认证

控制台接口使用平台网页登录 Cookie，不接受普通 API Bearer 替代。GET /auth/session 返回当前用户和 csrfToken。所有控制台写请求还需 Content-Type: application/json、Origin: https://awesome.guanghexinzhi.cn 和 X-CSRF-Token；DELETE 也需要这些请求头。

创建或撤销凭证、修改成员权限、密钥轮换等敏感操作需要最近 10 分钟内完成飞书登录。平台会话最长 8 小时，闲置 30 分钟失效。文中控制台请求示例仅供开发平台自身界面；同组网页请使用第 3 章，不复制平台 Cookie。

3. 同组接入服务接口

服务地址：http://127.0.0.1:8099。仅供与部署平台同机的可信业务后端调用；这些接口不能由浏览器直接调用。所有请求携带接入服务凭证。

3.1 搜索现有项目

搜索现有项目。

POST http://127.0.0.1:8099/apps/search

认证要求

接入服务凭证。

只返回当前共享登录用户有权部署的项目。选择返回的 appId 后可更新部署；不要自动选择搜索结果的第一项。

sessionId 表示当前操作者，ownerId 表示要筛选的当前项目负责人。ownerId 是平台用户 ID，不是飞书 open_id，也不是来源凭证持有人 ID。查询负责人不会切换登录身份、授予权限或改变项目归属。

先按真实用户的部署权限过滤，再按 ownerId 与 query 筛选，最后计算 total 和分页。未知或不可见的 ownerId 返回 items=[]、total=0，不泄露其他人的项目。下一页保持 sessionId、ownerId、query、limit 不变，仅将 offset 改为 nextOffset。ownerId 筛选只限定搜索结果，不代表已获得更新权限。负责人查找见 3.6 / 4.4；普通用户不会因同组服务 Key 而获得全局搜索权限。

10.2 接入请求状态与幂等重试

接入请求 status：pending（待投递）、submitted（平台已受理）、rejected（投递被拒绝），或同步到的 succeeded/failed/recovery_required/cancelled。业务执行原因查看 deployment.error；外层 error 主要记录投递问题。

幂等键允许 1–128 位字母、数字、点、下划线、冒号和中划线。调用方应在第一次发送前保存请求 ID 与申请人关联。响应丢失、超时或进程重启后，使用原 ID、原请求和原身份继续查询或重投。真正的新部署才创建新 ID。

普通自动化的幂等范围绑定具体 API 凭证；同组部署的幂等范围绑定来源和请求 ID。接入服务已保存的请求不依赖用户会话继续在线。来源凭证过期需维护，不能通过换申请人或换 ID 绕过权限。
