Awesome Deploy｜部署接入使用手册（0.11.2）

面向部署使用者、AI 与开发者。核对日期：2026-10-23；适用平台：0.11.2。完整字段和部署约束以部署接入技术协议 v2.0、平台当前资源限制、认证后的 JSON Schema 及实际错误为准。

业务代码边界：只部署用户提供的业务实现，不擅自增加、删除或修改业务逻辑。

需要可复制的文件时，直接查看技术协议中的单服务 awesome.yaml、持久存储与密钥完整清单、前端与 API 清单和Dockerfile 示例。本使用手册说明操作步骤；清单示例集中在技术协议第 5 章和第 6.1 节。

一、不可变更的业务边界

只部署用户提供的业务实现。不得增加、删除或修改业务逻辑、鉴权、数据模型、接口语义或依赖行为。

可以提供与原行为一致的 awesome.yaml、Dockerfile、镜像引用、构建产物和部署说明。

镜像固定摘要不授权替换业务实现。若适配必须修改业务代码，说明原因和所需变更，由用户另行决定。

不要关闭鉴权、删除数据库依赖、伪造健康检查，或用演示程序替换原应用以取得部署成功。

二、当前资源限制（平台 0.11.2）

当前配置：每应用持久数据合计 50 MiB；每应用运行内存预算合计 500 MiB，按需使用；平台共享存储池预算 64 GiB。活动版、候选版及待清理版本尚未释放的内存预留合并计入同一应用预算。在线更新预算不足时，可先下线并保留数据，再选择原应用部署。部署前仍应在平台页面查看实时配置。

多个服务按应用合计；各服务应显式填写 resources.memoryMiB，避免默认值叠加超限。

内存值是运行上限，实际占用随负载变化。超限可能被终止；存储写满会拒绝继续写入。

新建持久数据使用 schemaVersion: 2。每服务最多一个 /data 存储；sizeMiB、maxInodes 必须为正整数。

总申请须满足应用和平台预算。inode 还受服务器配置约束；JSON Schema 的字段上界不是当前可用配额。

三、仓库与文件

1. 使用 GitHub / GitLab HTTPS 仓库 URL，不嵌入账号、令牌、端口、查询参数或片段。

2. 网页部署默认使用 main，无需填写分支。请把源码与部署文件提交并推送到 main；API 可显式指定其他真实存在的分支、标签或完整 commit，省略 ref 时同样默认 main。

3. 仓库根目录放置 UTF-8 awesome.yaml，最大 256 KiB。YAML 不使用重复键、锚点、别名或显式标签。

4. 源码构建提交 Dockerfile 和完整构建上下文；使用已有镜像时在 image 与 build 中二选一。

5. 不依赖 Git submodule、Git LFS 下载或仓库符号链接。当前线上 Git 拉取已配置平台代理，但尚未配置私有仓库读取凭证；私有仓库须由管理员先配置授权。飞书登录不自动授予 GitHub/GitLab 权限。

6. 不需要额外提交 ZIP“交付包”；平台从仓库读取已提交的文件。

四、清单契约

必填顶层字段：schemaVersion、app、services、routes；禁止未定义字段。

app 必填 name、description、subdomain。部署表单中的“项目名称”用于生成访问域名，对应 API 的 subdomain 和清单中的 app.subdomain：1–7 位小写字母、数字或中划线，首尾为字母或数字；不能含中文、空格或大写字母，还要通过保留名称校验。清单的 app.name 是显示名称，可以使用中文。

services 为 1–16 个具名服务，当前只支持 kind: web。每服务必填 port、healthcheck，且 image/build 二选一。

服务名以小写字母起始，只含小写字母、数字和中划线，最长 31 字符。

build.context 相对仓库；build.dockerfile 相对 context；可选 target 和非秘密 args。

env 的值必须是字符串；secretRefs 只填写引用名，不填写秘密值。同一变量不得同时出现在两者中。

command、entrypoint 使用字符串数组；workingDir 使用绝对路径；不做 shell 或变量插值。

dependsOn 可填写 started 或 healthy，不允许不存在的服务或循环依赖。

routes 必填 path、match（exact/prefix）、service，可选 stripPrefix；网关最多 32 条，并执行额外路径校验。

声明 storage 时，挂载点固定 /data。schemaVersion 2 还必须填写 sizeMiB 和 maxInodes；新 XFS 存储从空目录开始，应用应按原有启动逻辑初始化。

五、构建与运行条件

运行用户为非 root（当前 65532:65532），根文件系统只读。持久文件写入已声明的 /data；临时文件仅写入平台允许的临时目录。

应用监听 0.0.0.0，并与 services.<name>.port 一致。Dockerfile 的 EXPOSE 不能代替实际监听。

HTTP 健康检查填写真实可用的路径；exec 健康检查使用容器内已有的命令数组。不要假设镜像内有 curl。

构建 RUN 默认不能访问外网。所需依赖应已在所选基础镜像或仓库构建上下文中；不能假设构建时可执行联网 npm/pip/apt 安装。

平台保持正常构建缓存。基础镜像会固定到摘要；不得通过禁用所有缓存作为常规部署方案。

Dockerfile 支持显式 FROM、RUN、COPY、ENV、WORKDIR、USER、EXPOSE、LABEL、CMD、ENTRYPOINT、ARG、STOPSIGNAL。

当前不支持续行、heredoc、自定义 frontend/parser、动态 FROM、RUN flags/mounts、ADD、VOLUME、ONBUILD、HEALTHCHECK；COPY flags 仅允许引用之前命名阶段的 --from=。

运行时网络由平台配置决定，见 /api/v1/capabilities；构建网络和运行网络是两个不同的限制。受限公网 HTTPS 模式允许公网 IPv4 TCP 443，不表示任意端口和私网均可访问。

不支持独立数据库/消息队列服务、后台 worker、数据库迁移钩子、主机目录挂载或任意 TCP/UDP 暴露。应用自身使用 /data 保存 SQLite 等文件不等于平台托管数据库。

六、密码与密钥

密码、API Key、令牌、MASTER_KEY 的实际值不得提交到 Git、env、build.args 或镜像中。

示例引用：secretRefs: {BOOTSTRAP_PASSWORD: BOOTSTRAP_PASSWORD, MASTER_KEY: MASTER_KEY}

缺少项目登录密码时，在部署页面设置；外部 API Key 填供应商签发的真实值，不能随机生成代替。

平台识别为托管主密钥的 MASTER_KEY 自动生成、加密保存并按应用复用；已有值不会在每次部署时重新生成。

其他随机密钥不能仅因名称含 KEY 就假定自动生成。应用必须与平台托管值格式兼容，不能要求平台改业务算法。

应用管理中的密钥页面显示名称、版本与状态，不回显已保存值。普通运行密钥可轮换/吊销；主密钥不支持普通轮换。

飞书登录用于部署控制台；平台会话连续 30 分钟无请求或自登录起满 8 小时后失效，需要重新登录。这是控制台会话规则，同组后端的 Redis 共享会话另按接入手册配置。业务应用的登录用户名、密码和初始化逻辑由该应用本身定义。

七、提交、更新和下线

首次部署选择创建新应用；更新或保留数据后重新上线时选择原应用。下拉框搜索在浏览器中筛选当前登录用户可见的应用，可输入项目名称、仓库地址或应用编号。普通自动化更新使用 POST /api/v1/automation/deployments，并传入原 appId；同组项目可通过专用委托来源凭证和有效共享会话 POST /api/v1/integrations/apps/search 搜索有权更新的项目，再使用返回的 appId 更新。进度通过任务 GET 接口读取，按 pollAfterSeconds 查询，terminal=true 时停止；具体见同组后端实施手册。

平台依次获取代码、固定输入、构建、启动、健康检查和验证 HTTPS。排队成功不等于上线成功。

有持久数据的更新可能短暂停机；回退应用版本不会撤销候选版本对数据的写入，数据格式须保持兼容。

下线可选择保留数据，或清除平台受控业务数据及该应用保存的密码、API Key、密钥。删除不可恢复，外部数据库不会自动删除。

确认下线与清理完成后才释放域名和运行端口。失败或待恢复状态可能继续占用资源；不能仅凭“部署失败”判断已释放。

部署失败时查看具体错误和当前应用状态，不自动修改用户源码，也不为重试随意删除已有数据或替换主密钥。

网页与自动化 API 提交的应用和部署任务均进入平台记录，由后台异步同步到飞书多维表格。负责人关联实际提交身份或凭证绑定的飞书成员；表格不是实时部署队列，飞书同步失败不使已受理部署失效。同组 A 端适配服务提供数据库持久受理和恢复投递，真实 A 业务尚待接入；旧独立登记模块的飞书部署请求表恢复未接入该链路。审批门禁、业务后台 worker 和自动备份仍未提供。

八、AI 交付检查清单

请先检查原项目，再提供实际所需的部署文件和简短操作说明。不要创建与业务无关的演示程序。

说明每个文件放置位置、端口、健康路径、所需引用名称及数据目录；不要在说明中放秘密值。

说明哪些限制已满足、哪些需要业务方决定，禁止把未验证事项写成通过。

飞书登录平台后，可通过网页登录会话访问 /api/v1/schema?version=2 核对字段；无存储旧项目可使用 version=1。这是控制台接口，不接受自动化 Bearer 凭证。

控制台接口 POST /api/v1/preflight 用于配置预检，请求体为 {"manifest":"清单 YAML 字符串"}，需网页登录会话、同源 Origin 和有效 X-CSRF-Token；自动化 Bearer 凭证不能调用。预检不会拉代码、构建、预留资源或保证最终上线。

实际构建与运行使用既有远端部署平台；未经用户要求，不自动启动本机 Docker Desktop。

验收应覆盖真实页面/API、真实健康路径、重部署及所声明的数据持久化行为。只做与本次交付相关的检查。
